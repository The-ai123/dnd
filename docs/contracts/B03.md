# B03 original assets and references

Originals live at `world-folder/assets/sha256/<lowercase-sha256>`. These are the exact imported bytes, with no decoding, re-encoding or embedded source filenames. Hash and byte length are stored in world schema 3. Catalog schema 1 and the world identity manifest remain unchanged. Schema 2 upgrades preserve records and mark their existing versions as having an empty asset set.

## Authority API

Keep a `WorldRepository` open in the authority process so it holds B02's exclusive world writer. Use `world.importAsset(sourceFile)` to copy an original and register its metadata. The lower-level `OriginalAssetStore` is also authority-only and requires that same writer ownership; do not publish from competing workers. The storage module is exported at `@dnd/assets/originals` so persistence need not initialize the sharp decoder.

Ingestion reads in 1 MiB chunks, hashes the bytes actually copied, handles partial writes, flushes and closes an exclusively created temporary file in the hash directory, then renames it into the hash address. Existing originals are verified and reused without replacement. Corrupt duplicates fail rather than being silently overwritten. Metadata registration happens only after verification of the published file. Internal linked directories, linked originals and invalid hash paths are rejected. Source imports must be regular files with one link.

Call `world.write(record, links, assetHashes)` with the complete set of original hashes referenced by that record version, including embedded document images. Omitting the third argument means an empty set. The repository requires registration in this world, rechecks published bytes and length, then writes the version's asset references, current record and record links in one SQLite transaction. A missing/corrupt/unregistered asset or failed record/link write cannot leave a new committed reference. Hash arrays are normalized as sets.

The asset set of an existing `(kind, recordId, version)` is immutable, including an empty set. Replacements must use a new version. Earlier asset references remain retained when the current record advances. There is intentionally no cascading owner deletion, reference removal, original eviction or garbage-collection API. B04 still owns version-conflict checks, atomic commands and the full revision journal; B07 owns historical document payloads. B03 does not turn B02's current-record table into document history.

`world.assetsFor({ kind, recordId })` returns the current version's hashes; supply a version to read the retained historical set. `world.referencedAssets()` returns the deduplicated metadata union across all retained versions for C01's future consistent backup manifest. Neither query is a backup or a validation of externally modified files. Use `OriginalAssetStore.verify(hash)` to check bytes and `path(hash)` only within authority code. Renderers must receive future role/scene-bound asset projections, never these raw disk paths.

## Failure and retention behavior

- Failure before publication leaves no registered asset. Ordinary exceptions clean up the temporary file; process exit can leave an ignored `.ingest-*.tmp` file.
- Exit after publication but before metadata registration leaves an unreferenced original. Retrying the import verifies and registers that original.
- Exit after registration but before a record write leaves registered, unreferenced bytes. These are retained safely; no automatic pruning is authorized.
- `derived/` is independent of original metadata and references. Tiles can be deleted and rebuilt without editing historical references or originals.

The process-exit guarantees use local filesystem atomic rename plus flushed file data and SQLite FULL synchronous commits. Fault tests cover application process exits; they do not certify storage hardware against power loss. B08 owns orphan/intent recovery workflows, C01 owns backup consistency and E02 owns image-format/resource preflight, cancellation and production tile jobs. Ingestion here preserves arbitrary bytes without decoding them and runs synchronously in the authority utility process with bounded copy memory.
