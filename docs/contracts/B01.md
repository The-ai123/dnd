# B01 domain and IPC boundary

Protocol version 1 uses `storyteller:request` and `player:request`. The sandboxed preloads expose named capabilities, never `ipcRenderer`, filesystem paths or SQL. The host verifies its registered webContents role and the sender's main frame before parsing the corresponding role-specific schema. A submitted `actorWindowRole` cannot grant capabilities. The engine parses again inside its serialized queue and compares world-instance IDs with its current authority.

All envelopes and nested objects are strict. UUIDs identify worlds and records; display names never do. Revisions are nonnegative safe integers. Unknown fields, unknown operations, unsupported protocol versions, duplicate version expectations, and renderer paths/scripts are rejected. No arbitrary JSON mutation operation exists. Types are inferred from the runtime schemas, while the domain package stays framework-independent.

## Requests and results

Every request carries `protocolVersion`, `requestId`, `actorWindowRole` and a discriminating `operation`.

| Operation | Role | Binding / result |
| --- | --- | --- |
| `host.snapshot` | Either | Bootstrap current host view, no supplied world; role-specific snapshot |
| `host.open-player` | Storyteller | Host-only capability; acknowledgement |
| `world.snapshot` | Either | Required `worldInstanceId`; role-specific snapshot |
| `scene.select` | Player | Required world binding plus full scene identity and visible token ID; acknowledgement |
| `session.create` | Storyteller | World, command ID, expected versions, new session/campaign IDs, optional continuation; handler not installed |
| `session.complete` | Storyteller | World, command ID, session ID, expected versions; handler not installed |

Bootstrap snapshots intentionally follow the current host world. An editor or mutation must retain its explicit world binding; never use a bootstrap query to retarget an old command after a world switch. Scene selection additionally checks nested world identity, scene epoch, revision, live context and visible membership. Presentation revision is not a substitute for expected record versions.

Success results discriminate private/public snapshots, transient acknowledgements and durable commits. A durable commit carries command ID, world ID and committed revision. Failures discriminate invalid request, unauthorized sender, world mismatch, unsupported operation, invalid selection, version conflict and internal failure. Internal exceptions/stacks/paths are not serialized. Invalid/untrusted requests have a null response request ID; parsed requests retain their correlation ID. Host responses are validated and checked for expected role/result type before returning to a renderer.

## Version and domain contracts

An expected version identifies record kind, record ID and a nonnegative revision, or null for required absence. Null never means “ignore conflicts.” Creation requires session absence and an existing campaign version. Completion requires an existing session version. `findVersionConflicts` reports all mismatches, including creation collisions and deletion. `validateCommandVersions` encodes the structured conflict result; future handlers must call it using a world-bound repository lookup inside their transaction before writes. Handlers must also require all operation-specific read/write dependencies, beyond these minimum envelope requirements.

Session status is `in-progress` or `complete`, without a durable paused state. Reservations identify owning session and canonical record. Placements reference canonical entities and contain position/footprint, without copied HP/inventory. World qualification is explicit at IPC boundaries; internal links remain UUIDs so separate restored worlds can preserve links. B05 enforces completed-session freezing, uniqueness, reservations, clock handoff and relationship existence.

The bounded formula DTO represents a sum of signed constants/dice terms (up to 32 terms, 100 dice per term and 1,000 sides). It accepts no executable expression text. These are parser resource limits, not tabletop rules limits; unsupported authoring text remains manual in future editors. F03 owns parsing, evaluation and full rule-resolution semantics. Pending A05 fields and source catalog schemas are deliberately not invented here.

## Evidence and downstream obligations

Integration tests exercise malformed/nested/extra data, role escalation, sender/subframe rejection before dispatch, world mismatches, conflicts, result sanitization and domain bounds. The packaged smoke test exercises foreign/current world queries, unavailable lifecycle execution, malformed requests, live/stale selections, unregistered sender rejection and window reopening, alongside the existing privacy/native/WebGL checks.

B01 provides the boundary and schema contracts. The architecture shell still runs a synthetic world. Lifecycle commands return `UNSUPPORTED_OPERATION` and cannot acknowledge a durable commit. B02 owns repositories/migrations; B04 owns transactional execution, command deduplication and publication after commit; B05/B06 own lifecycle/reservations/history. Retries must retain `commandId` while request IDs may change. No idempotency, backup gate or gameplay completion is claimed by schema validation.
