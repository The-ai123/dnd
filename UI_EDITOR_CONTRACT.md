## 2. Shared editor, validation and recovery behavior — R01

**Two values:** preserve raw typed text in a durable editor draft, separately from the last validated gameplay/content value. Empty numeric input, `-`, partial decimal, invalid reference or malformed expression never silently becomes zero, clears a committed field or affects gameplay. A draft acknowledgement means its raw input is durable, not that it is valid game state.

**Approved save triggers, October 27:** single-line fields commit/save on leaving the field or pressing Enter. Multiline notes use Enter for a new line, Ctrl+Enter or field departure to commit. No inactivity timer, debounce save or per-keystroke durable write. While typing, retain the edit in memory and show Editing · Not saved; do not display Saving until an actual commit request begins. At the trigger, preserve raw invalid input as a draft, retaining the last valid gameplay value; valid input applies through the validated engine command. Acknowledgement is still required before saying Saved. An interrupted application can lose uncommitted typing; do not claim restart recovery for that text. Semantic edit groups are per explicit commit/field departure; multi-field operations are explicit groups. A field with dependent errors cannot publish a partially valid aggregate. Gameplay commands retain whole-action grouping and linked phases; hover/scroll/panel closure itself is not a gameplay action, although leaving an edited field triggers its commit. IME composition Enter completes composition, not an unintended form commit.

**Approved numeric baseline:** trim outer whitespace; accept ordinary decimal notation with an optional sign where the field permits it; reject nonfinite values, scientific notation, thousands separators and trailing junk. Counts are integers. Length/speed/elevation use feet; durations display an explicit unit and store their supported exact representation. Display rounding does not change stored values. Creature fields and HP baseline in section 9 are approved: whole current HP ≥0, max HP ≥1, temp HP ≥0; above-max current requires a labeled storyteller override and is preserved, temp HP excluded from health ratio. Ability scores/derived rule limits come from the selected, versioned supported rules; this contract does not invent SRD rules.

**Required fields:** mark required visibly. Approved: nonempty names/titles up to 120 characters, nonempty tags up to 40 characters, duplicate tags removed case-insensitively, display names need not be unique and IDs distinguish records. Trim outer whitespace; descriptions/notes may be empty. There is no product tag-count cap. Reference pickers store qualified record/version IDs, display scope and detect deleted/unavailable references. New records receive IDs when their drafts are created but cannot be used in gameplay/generation until valid.

| Editor state | Visible status / actions | Authoritative behavior |
| --- | --- | --- |
| No edits | Saved | Last acknowledged valid value |
| Typing before field departure/Enter | Editing · Not saved | In-memory text only; no timer persistence/application |
| Pending request | Saving… | Preserve draft; do not claim durability |
| Raw draft durable, invalid field | Draft saved · Fix highlighted fields; error adjacent to field | Retain previous valid gameplay value; show that value next to invalid field where needed |
| Valid save acknowledged | Saved; revision accessible from Version History | Apply validated edit through engine/history |
| Permission/disk failure | Not saved · error · Retry; Copy unsaved text | Retain in-memory text and previous valid value; never claim restart recovery for unacknowledged text |
| Version conflict | Conflict · Compare current / Keep my draft / Reload current | Preserve both drafts; no silent overwrite or last-writer-wins. Reapply requires current versions and validation |
| Reserved record | Read only · session name · Open Session | Block manager mutation; inspection remains available |
| Completed session / replay / built-in source | Read only · reason; permitted Continue / Copy to campaign action | No edit shortcut or inspector bypass |

Approved failure/conflict recovery: retain typed text, show Not saved or Conflict, and offer Retry/Compare/Copy as appropriate. Leaving the world or exiting requires resolving pending edits or explicitly choosing to leave without them; copying/exporting text preserves it externally but is not a successful world save and does not silently dismiss that warning. Ordinary successful editor navigation needs no Save/Discard dialog; durable invalid drafts can be revisited without blocking navigation. Stage discard, world empty-trash and destructive replacement use specific confirmations. An internal Retry retains the same command ID; new intentional edits receive new IDs.

**Version history:** one list ordered newest first with timestamp, actor/source, changed fields, valid/draft state and owning session if any. Compare before restore/apply; restoring an old definition produces a new current revision rather than deleting later history. Completed-session fields remain frozen. Draft checkpoints never replace the valid revision used by entities. Exact journal mechanics are B07, not part of this UI mockup.

**Error hierarchy:** syntax/required/type/reference/storage/ownership conflicts block application; field-domain problems that cannot form valid state block; permitted action/resource overspend, manual stock over-budget and labeled storyteller rule overrides warn and can proceed. A rule override never bypasses schema validity, reservations, forbidden public data or the backup gate. Unsupported custom mechanics are visibly manual, not presented as supported automation.

## 3. Shell, dimensions and Home — R02

All dimensions are logical CSS pixels at 100% application scale. A 3840×2160 display at 200% OS scaling provides roughly the same logical workspace as 1920×1080 at 100%; no control shrinks with map zoom. UI scale choices: 90%, 100%, 110%, 125%, 150%; default 100%. Default Comfortable: 14px body, 12px secondary, 20px line height, 36px control/row minimum. Dense: 13px body, 12px secondary, 18px line height, 28px controls/rows. Touch-accessible controls expand to 44px where coarse pointer applies. Visible focus ring and text labels remain in both modes.

Top bar 44px, workspace tab strip 36px, status strip 24px at Comfortable; Dense 36/30/22px. Top bar: world/campaign picker, World Manager, selected session/status with Resume/New/Mark Complete, player-window toggle and save state. Context menus repeat destructive/session actions rather than packing all into the top bar. One tab per qualified record, one Play per campaign; Home remains accessible. Restore tabs/focus per campaign; unavailable tab shows Locate/Remove shortcut without deleting data. Chooser is fallback when world cannot be opened.

Home uses the approved eleven labeled buttons in the existing order, a four-column grid at ≥1200px available content width, three at ≥800px, otherwise two (one below 420px). Below: Resume (session, date, encounter, reservation status), party rows (name/level/HP/status), prepared areas (name/location/draft badge) and recent durable activity (time/record/change). Empty states provide Create Campaign, Add Character or Create Area as appropriate. No decorative charts or arbitrary scores. Opening tools never changes public presentation or game time.

Table screens use a 240px optional filter/category rail, flexible list and 360px details preview at 1920px; user-resizable and collapsible. Table scroll and detail scroll are independent. Under 1280px logical width, detail becomes a disclosed side panel; under 960px, filters become a drawer and details a separate view. Preserve visible primary actions and keyboard access. Narrow review previews reflow; they are not evidence of a 1080p/4K or mixed-DPI runtime pass.

## 7. Sessions, documents and recovery — R03

Before creation show party/reservation status and backup destination; conflict offers Open Owning Session or Cancel. Mark Complete summarizes reservations released and freezes all fields after confirmation. Continue explains present-state start and source link. In Progress title/notes/tags autosave through session ownership; completed controls are read-only. Separate new/current notes can link to a sealed session without editing it.

Approved document fields: session notes/lore/quests have title*, rich text, tags, images and record links. Quests add editable statuses defaulting to Not Started, Active, Completed, Failed and On Hold. Completed-session fields stay frozen. Show scope and owner; rich text supports headings/paragraphs/lists; status labels/order use stable IDs per world. No automatic rewards/progress or nested wiki hierarchy. Deleting linked content shows a broken-reference placeholder and usage warning; never silently retarget by name.

History list selects session then action group with timestamp, creature/source, summary and affected records. Undo/Redo show affected context and reason when blocked; completed sessions read-only. Replay toolbar: Play/Pause, speed 0.5×/1×/2×/4×, Step Back/Forward, seek. Storyteller/private versus player/historical visibility is explicit; replay never sends mutations. Exit Replay returns to current live context without resetting it.

Data & Backups: world/path, last successful backup, backup destination, required-operation status, history points, export/import and Trash. Trash list: world name, deleted date, original path, associated backup count/total bytes; Restore or Empty Selected/All. Permanent deletion confirmation lists exact owned worlds/backups and totals. Collision restore offers Choose New Folder / Cancel; no replace existing directory. Interrupted archive/trash work shows resumable operation status; exact filesystem recovery is C03/C04.

## 13. Loot tables, generation drafts and shop stock — R05

Table: name*, tags, ordered tier IDs/labels, per-tier multiplier finite ≥0, entries with item/version reference, tier, base chance decimal 0–100%, priced-unit quantity, integer-gold price and eligibility notes. Entry chances independent, never normalized. **Approved currency correction: gold is an integer; some items may be bundled to compensate.** Prices, budgets, line/stock totals and unspent/excess values are nonnegative whole gold. Fractional-gold input is an invalid draft, never silently rounded or converted to copper. A priced unit contains a positive integer number of an item; default 1, with an explicit authored bundle quantity when needed. Example: five items priced together at 1 gold is one priced bundle; no fractional per-item valuation is introduced.

One successful generator addition adds one authored priced unit: one item or one complete bundle. Bundle count and total physical item quantity are distinct, visible fields. Each addition uses the full bundle price for affordability and duplicate-chance reduction; the approved halving counter increments once for that addition, not once per bundled item. Generator does not infer bundles, split bundles or alter authored probabilities to compensate. Paid generation requires a positive whole-gold price. Manual stock may have a zero-gold price per priced unit. Zero-gold entries are ineligible for automatic budget generation.

Generator: shop/name, table/version, selected tier, total budget, target percentage 0–100 (default 70), max passes positive integer (default 10), tier multipliers and preview of eligible values. Do not introduce the earlier unapproved maximum of 100 passes; technical cancellation/resource diagnostics do not silently change requested output. Use approved cap-then-halving/shuffle/affordability/stop algorithm; record outputs/rolls. Target 0 or budget 0 yields empty draft, no forced additions. New generation resets successful-addition counters.

Draft: item reference, bundle count, items per priced unit, total item count, integer-gold price per priced unit, whole-gold line total, stock total/budget/unspent or excess, provenance and generation stop reason. All gold amounts and counts are nonnegative integers; items per priced unit is at least 1. For singles, items per priced unit =1. A bundle-count edit changes total units explicitly; there is no fractional bundle count. Manual over-budget edits warn but can Finalize. Save the draft separately on approved commit triggers; opening/switching/restart never rerolls. Regenerate previews destructive replacement of draft rows and requires confirmation; retain finalized stock until successful Finalize. Cancel offers Keep Draft or confirmed Discard, never changes finalized stock. Finalize creates/replaces shop stock atomically with version history; purchases/transfers remain manual inventory/currency changes.

Acceptance: a zero-gold entry is skipped in automatic generation and can be added manually and finalized with a zero-gold line total.
